# 사용 가이드

처음 여는 분은 **순서대로** 따라오세요. 특히 5단계(모의투자 검증)를 건너뛰지 마세요.

> ⚠️ 이 앱은 투자 자문이나 수익 보장을 제공하지 않습니다.
> 모든 매매 결과와 손실은 사용자 본인의 책임입니다. 자세한 내용은 `risk-and-compliance.md`를 읽어주세요.

## 0. 준비물

| 항목 | 설명 |
|---|---|
| 안드로이드 기기 | **Android 8.0 (API 26)** 이상 |
| Android Studio | 최신 안정 버전 (Koala 이상 권장) |
| JDK 17 | Android Studio 내장 JDK로 충분 |
| 증권사 계좌 | 한국투자증권 계좌 (비대면 개설 가능) |
| API 사용 신청 | 한국투자증권 개발자센터(KIS Developers)에서 신청 |

## 1. API 키 발급받기

1. 한국투자증권 계좌를 개설합니다.
2. 한국투자증권 **개발자센터(KIS Developers)** 에 접속해 로그인합니다.
3. **Open API 이용 신청**을 하고 약관에 동의합니다.
4. 신청이 완료되면 **APP KEY**와 **APP SECRET**이 발급됩니다.
5. **모의투자용 키는 실전용과 별개입니다.** 모의투자를 쓰려면
   모의투자 계좌를 따로 신청하고, 모의투자 전용 APP KEY를 별도로 발급받아야 합니다.

발급받아야 하는 값 4가지:

- `APP KEY`
- `APP SECRET`
- `계좌번호 앞 8자리` (예: `50123456`)
- `계좌상품코드 뒤 2자리` (보통 `01`)

> 📌 개발자센터의 메뉴 이름과 화면 구성은 바뀔 수 있습니다. 위 순서가 다르면 **공식 안내를 우선**하세요.

> 🔒 APP SECRET은 비밀번호와 같습니다. 캡처해서 메신저로 보내거나, 소스코드·깃 저장소에 넣지 마세요.

## 2. 빌드하기

```bash
git clone <이 저장소>
cd android-stock-trader
```

Android Studio에서 `android-stock-trader` 폴더를 **Open** 합니다.
Gradle 동기화가 끝나면 기기를 연결하고 실행(▶)하면 됩니다.

명령줄에서 빌드하려면:

```bash
./gradlew :app:assembleDebug        # APK 생성
./gradlew :core-trading:test        # 매매 로직 단위 테스트 (에뮬레이터 불필요)
```

> `core-trading` 테스트는 안드로이드 SDK 없이도 돌아갑니다. 전략이나 리스크 로직을 손봤다면
> 기기에 올리기 전에 이 테스트부터 돌리세요.

### (선택) 개발 중 키 자동 입력

매번 키를 타이핑하기 번거로우면 프로젝트 루트의 `local.properties`에 넣어둘 수 있습니다.
이 파일은 git에 올라가지 않습니다.

```properties
kis.appKey=발급받은_APP_KEY
kis.appSecret=발급받은_APP_SECRET
kis.accountNo=50123456
```

앱 최초 실행 시 한 번만 자동으로 채워집니다. **릴리스 빌드에는 쓰지 마세요.**

## 3. 앱 최초 설정

### 3-1. 투자 모드 확인 — `설정` 탭

기본값은 **모의투자**입니다. 이 상태를 유지하세요.

### 3-2. API 인증 정보 입력 — `설정` 탭

APP KEY / APP SECRET / 계좌번호 8자리 / 상품코드를 입력하고 **저장**합니다.
입력값은 안드로이드 키스토어로 암호화되어 기기 안에만 저장되며, 외부로 전송되지 않습니다.

### 3-3. 연결 확인 — `대시보드` 탭

**새로고침**을 누릅니다. 총 평가금액과 주문가능현금이 표시되면 연결에 성공한 것입니다.

연결이 안 될 때:

| 증상 | 확인할 것 |
|---|---|
| `토큰 발급 실패` | APP KEY/SECRET 오타, 모의투자 키를 실전 모드에 넣었는지 |
| `잘못된 tr_id` 류 오류 | `KisEndpoints.kt`의 TR_ID를 개발자센터 최신 문서와 대조 (아래 §7 참조) |
| 계좌 조회만 실패 | 계좌번호 8자리 / 상품코드 2자리 분리가 맞는지 |
| 응답이 아예 없음 | 기기 네트워크, 증권사 서버 점검 여부 |

## 4. 매매 대상과 전략 설정

### 4-1. 종목 등록 — `대시보드` 탭

종목코드 6자리를 입력하고 **추가**합니다. (예: 삼성전자 `005930`)
등록된 종목은 스위치로 개별 on/off 할 수 있습니다.

**처음에는 1~2종목으로 시작하세요.** 종목이 많을수록 API 호출이 늘어 한도에 걸리기 쉽고,
무엇이 잘못됐는지 파악하기도 어려워집니다.

### 4-2. 전략 선택 — `전략` 탭

| 전략 | 유리한 장세 | 불리한 장세 |
|---|---|---|
| 이동평균 교차 | 추세가 뚜렷한 상승/하락장 | 횡보장 (잦은 손절) |
| RSI 역추세 | 박스권 | 지속 하락 추세 |
| 볼린저 평균회귀 | 변동성이 일정한 박스권 | 강한 추세 돌파 |
| MACD 교차 | 중기 추세 전환 구간 | 단기 급등락 |

**모든 장세에서 통하는 전략은 없습니다.** 아래 백테스트로 직접 확인하세요.

### 4-3. 안전장치 설정 — `전략` 탭 하단

처음에는 **보수적으로** 시작하는 것을 권합니다.

| 항목 | 처음 권장값 | 의미 |
|---|---|---|
| 기록 전용 모드 | **켜짐** | 신호만 기록, 실제 주문 안 함 |
| 종목당 최대 비중 | 5% | 1,000만원 계좌면 한 종목 최대 50만원 |
| 최대 보유 종목 수 | 3 | |
| 손절 | 2~3% | **0으로 두지 마세요** |
| 익절 | 4~6% | |
| 일일 손실 한도 | 3% | 도달 시 당일 신규 매수 중단 |
| 일일 최대 주문 건수 | 10 | 오작동 시 폭주 방지 |
| 현금 버퍼 | 30% | 총자산의 30%는 매수에 미사용 |
| 재주문 쿨다운 | 5분 | |
| 실행 주기 | 60초 | 짧을수록 API 한도에 걸리기 쉬움 |

각 항목을 바꾼 뒤 **안전장치 저장**을 누르세요.

## 5. 백테스트로 먼저 확인하기 — `백테스트` 탭

종목코드와 초기 자금을 넣고 **백테스트 실행**을 누르면,
현재 저장된 전략과 안전장치를 과거 일봉에 그대로 적용한 결과가 나옵니다.

읽는 법:

| 지표 | 의미 | 주의 |
|---|---|---|
| 총수익률 | 기간 전체 수익률 | 단독으로 보면 안 됨 |
| **최대낙폭(MDD)** | 고점 대비 최대 하락폭 | **가장 중요.** 이 낙폭을 견딜 수 있는지가 실전 지속 여부를 결정 |
| 승률 | 이긴 거래 비율 | 높다고 좋은 게 아님(작게 여러 번 벌고 크게 한 번 잃는 패턴) |
| 손익비(PF) | 총이익 ÷ 총손실 | **1.0 미만이면 비용조차 못 이긴 전략** |
| 샤프지수 | 변동성 대비 수익 | 높을수록 안정적 |

> 💡 총수익률이 높아도 MDD가 40%라면, 실제로는 중간에 못 버티고 꺼버리게 됩니다.
> **MDD가 감당 가능한 수준인 전략**을 고르세요.

백테스트의 한계는 `requirements.md` §4에 정리되어 있습니다. 절대 과신하지 마세요.

## 6. 실행하기

### 6-1. 1회 실행으로 점검

`대시보드` 탭의 **1회 실행**을 누르면 장 시간이 아니어도 한 사이클이 돕니다.
`매매일지` 탭에서 결과를 확인하세요.

매매일지에는 **주문하지 않은 이유도 남습니다.**

```
주문 보류 · 005930 삼성전자
골든크로스: SMA5(71,240.00) > SMA20(70,880.00) → 종목 비중 한도 도달 (한도 500,000원, 보유 712,400원)
```

이 기록을 보고 한도가 의도대로 동작하는지 확인하세요.

### 6-2. 자동 실행 켜기

**시작**을 누르면 포그라운드 서비스가 뜨고 주기적으로 매매 루프가 돕니다.
상단 알림에 마지막 사이클 결과가 표시되며, 알림의 **중지** 버튼으로 즉시 멈출 수 있습니다.

실행 조건:
- API 인증 정보가 저장되어 있을 것
- 활성화된 대상 종목이 1개 이상 있을 것
- 정규장 시간일 것 (주말·휴장일, 09:05 이전, 15:20 이후에는 건너뜁니다)

### 6-3. 배터리 최적화 해제 (중요)

제조사 배터리 최적화가 포그라운드 서비스를 강제 종료하면 **매매가 조용히 멈춥니다.**

`설정 → 앱 → AutoTrader → 배터리 → 제한 없음(최적화 안 함)`

경로는 제조사마다 다릅니다. 삼성은 `배터리 → 백그라운드 사용 제한`,
샤오미·오포 등 중국 제조사 기기는 별도의 자동 실행 허용 설정이 추가로 필요할 수 있습니다.

> ⚠️ 그래도 100% 보장되지 않습니다. **앱만 믿고 방치하지 마세요.**
> 실계좌 운용 시 증권사 앱에서 별도의 스탑로스 주문을 병행하는 것을 강하게 권합니다.

## 7. 실전투자로 전환하기

> 🚨 아래 조건을 **모두** 만족하기 전에는 전환하지 마세요.

체크리스트:

- [ ] 모의투자에서 **최소 2주 이상** 기록 전용 모드로 돌려봤다
- [ ] 매매일지를 읽고, 왜 사고 팔았는지 전부 설명할 수 있다
- [ ] 손절이 실제로 발동하는 것을 매매일지에서 확인했다
- [ ] 일일 손실 한도(킬 스위치)가 걸리는 것을 확인했다
- [ ] 백테스트 MDD를 실제 금액으로 환산해보고 감당 가능하다고 판단했다
- [ ] 잃어도 생활에 지장 없는 금액만 투입한다
- [ ] `KisEndpoints.kt`의 TR_ID를 개발자센터 최신 문서와 대조했다

전환 순서:

1. `설정` 탭에서 **실전투자** 선택 → 확인 대화상자에서 승인
2. 실전용 APP KEY / APP SECRET / 실계좌번호로 **다시 저장**
   (모의투자 키는 실전 서버에서 동작하지 않습니다)
3. `대시보드`에서 **새로고침**하여 실계좌 잔고가 맞는지 확인
4. **기록 전용 모드를 켠 상태로** 며칠 더 돌려보며 신호를 검증
5. 그 후에야 `전략` 탭에서 기록 전용 모드를 끄고 **시작**

기록 전용 모드가 꺼진 상태에서 시작을 누르면 **실제 주문이 나간다는 경고 대화상자**가 뜹니다.
이 경고를 읽지 않고 넘기지 마세요.

### TR_ID 대조가 필요한 이유

주문·잔고 API의 거래 코드(`TR_ID`)는 증권사가 개편하면 바뀝니다.
이 앱은 해당 상수를 `app/src/main/kotlin/com/sk/autotrader/data/remote/KisEndpoints.kt`
한 곳에 모아두었으므로, 값이 달라졌다면 그 파일만 고치면 됩니다.

```kotlin
object Tr {
    const val BUY_REAL = "TTTC0802U"
    const val SELL_REAL = "TTTC0801U"
    const val BUY_PAPER = "VTTC0802U"
    const val SELL_PAPER = "VTTC0801U"
    const val BALANCE_REAL = "TTTC8434R"
    const val BALANCE_PAPER = "VTTC8434R"
}
```

**반드시 모의투자에서 주문 왕복을 한 번 성공시킨 뒤** 실전으로 넘어가세요.

## 8. 자주 겪는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| 신호는 나는데 주문이 안 나감 | 기록 전용 모드가 켜져 있음 | `전략` 탭에서 해제 (실계좌면 신중히) |
| `주문 보류`만 계속 쌓임 | 한도에 걸림 | 매매일지의 거절 사유를 그대로 읽으면 원인이 나옴 |
| `일일 손실 한도 도달` | 킬 스위치 작동 | 정상 동작입니다. 다음 거래일에 자동 해제 |
| 호출 관련 오류가 잦음 | 실행 주기가 짧거나 종목이 많음 | 주기를 늘리거나 종목 수를 줄이기 |
| 밤새 돌렸는데 기록이 없음 | 서비스가 종료됨 | 배터리 최적화 해제 (§6-3) |
| 매매일지가 비어 있음 | HOLD는 기록하지 않음 | 거절 사유가 있을 때만 남깁니다 (정상) |
| 지표값이 HTS와 다름 | 수정주가 반영 여부 차이 | `MarketDataRepository`의 `adjusted` 인자 확인 |

## 9. 안전하게 쓰기 위한 습관

1. **매일 매매일지를 읽으세요.** 자동매매의 유일한 통제 수단입니다.
2. **한도를 먼저 정하고 전략을 고르세요.** 순서가 반대면 한도가 전략에 맞춰 느슨해집니다.
3. **설정을 바꾸면 기록 전용 모드로 며칠 돌리세요.** 특히 손절·비중 한도를 바꿨을 때.
4. **증권사 앱의 스탑 주문을 병행하세요.** 앱이 죽어도 남는 유일한 안전망입니다.
5. **수익이 났다고 한도를 올리지 마세요.** 한도를 올린 직후가 통계적으로 가장 위험합니다.
